# Jev и fine-tuned BERT

Минимальный клиент на стандартной библиотеке Python и подготовка общего корпуса.
Зависимости объявлены в `pyproject.toml`, версии зафиксированы в `uv.lock`.
Проект использует Python 3.14 (`.python-version`); `uv sync` устанавливает
зависимости в `.venv`. Клиент Jev использует стандартную библиотеку.
В `.env` хранится только `TYPESAFE_API_KEY`. Настройки Jev — глобальные переменные
в начале `jev.py`; настройки обучения и оценки BERT — в начале `bert/train.py`.
Данные находятся в `data/`, ответы — в `results/`.

## Запуск

```sh
cd /Users/pavelfilippenko/Projects/MyProjects/jev-bert-benchmark
uv sync --locked
uv run jev.py
```

Ключ не попадает в результаты. Реальный запуск делает платные API-запросы.
Результат записывается в `results/jev.jsonl`: ID примера, запрошенная модель,
хеш запроса, полная ответная структура (включая фактическую версию и usage)
и время HTTP-вызова. Существующий результат не перезаписывается; для нового
запуска задайте `--output results/run-02.jsonl`. Автоматических повторов запросов
нет. При ошибке уже полученные ответы сохраняются, запуск прекращается.

Официальная документация: https://docs.typesafe.ai/introduction/quickstart
Endpoint: `POST https://api.typesafe.ai/v1/systemone`.
Для воспроизводимого эксперимента задайте `--model` с доступной фиксированной
версией вместо обновляемого `jev-latest`; проверьте фактическую версию в ответе.

## Варианты задач

| Задача | Jev | BERT | Разметка |
|---|---|---|---|
| Тема обращения: billing/technical/sales/other | Choice | Классификация, 4 класса | Главная просьба клиента |
| Срочность обращения | Noul | Бинарная классификация | Явная немедленная просьба или текущая остановка работы/продаж |
| Тон: негативный/нейтральный/позитивный | Score | Классификация, 3 класса | Выраженная эмоция, а не факт наличия проблемы |
| Соответствие фрагмента поисковому запросу | Noul | Классификация пары текстов | Релевантен / нерелевантен |
| Подтверждение утверждения источником | Choice | Классификация пары текстов | Подтверждается / противоречит / недостаточно сведений |
| Совпадение двух товаров | Noul | Классификация пары описаний | Один товар / разные товары |

Начать предлагается с поддержки: один корпус позволяет проверить все три
примитива. Последние три задачи потребуют других вопросов и схемы корпуса;
текущий клиент реализует только первые три. Для Score сопоставляйте ожидаемое
значение score с порядковой оценкой BERT, а распределение вероятностей — с
вероятностями трёх классов. Score может быть дробным; для классов используйте
argmax распределения, а не округление score.

## Корпус и разбиение

Формат JSONL показан в `data/demo.jsonl`: `id`, `group_id`, `text`, `labels`,
`source`. Метки: topic — строка, urgent — 0/1, sentiment — 0/1/2.
Шесть ручных демонстрационных записей проверяют клиент; это не обучающий
корпус и не доказательство качества моделей.

План первого корпуса: около 3 000 независимо размеченных русскоязычных
обращений. Целевое соотношение train/validation/test — 70/15/15, фактическое
число зависит от групп. Храните source, язык, дату и происхождение разметки;
не передавайте служебные метки моделям. Желательно два аннотатора на спорных
примерах и тесте, затем разрешение разногласий по письменным правилам.
Добавьте отрицания, опечатки, короткие сообщения и несколько тем в одном тексте.
Отдельно определите правило для смешанного тона до начала разметки.

Разбиение уже подготовлено в `data/authored-v2/`: `train.jsonl`,
`validation.jsonl` и `test.jsonl`. Клиент Jev читает готовые данные.
Для общего теста используйте одинаковые пути `INPUT_FILE` в `jev.py` и `TEST_FILE` в `bert/train.py`.

```sh
uv run jev.py
```

Все варианты одного сценария находятся в одной части корпуса.
Зафиксированный тест не меняйте ради улучшения результатов.

## План сравнения

1. Выбрать pretrained BERT, подходящий для русского языка. Обучать отдельную
   классификационную голову для каждой из трёх задач либо явно зафиксировать
   многозадачную архитектуру. В `bert/train.py` реализованы три отдельных классификатора RuBERT.
2. Fine-tune только на train; подбирать гиперпараметры, Jev-инструкции,
   порог срочности и калибровку исключительно на validation.
3. Сравнить BERT с Jev zero-shot на одном закрытом test. Отдельно обозначить
   режим Jev few-shot, если примеры из train будут добавлены в контекст.
   Оба подхода получают одинаковый текст. Ограничить длину корпуса общим
   лимитом BERT или отдельно измерить влияние усечения.
4. Измерить macro-F1, accuracy, метрики по классам; для срочности также
   precision/recall и PR-AUC; для порядковой оценки — MAE. Сравнить Brier score,
   log loss и калибровку вероятностей. Jev confidence не считать вероятностью
   выбранного класса: использовать probabilities/Noul.
5. Считать парные доверительные интервалы по независимым группам. Для BERT
   выполнить несколько seed обучения. Сравнить кривую качества при 100/500/
   1 000/полном train, чтобы увидеть влияние затрат на разметку.
6. Измерить p50/p95 задержки и пропускную способность: Jev включает сеть,
   локальный BERT — токенизацию и inference после прогрева. Указать устройство,
   batch size, три вопроса на HTTP-вызов против трёх голов BERT. Отдельно
   учесть обучение, API usage, стоимость инфраструктуры и ошибки API.

## Обучение и оценка BERT

Параметры BERT находятся в начале `bert/train.py`. Модель по умолчанию:
`DeepPavlov/rubert-base-cased`. `BERT_REVISION` можно зафиксировать на commit ID
модели. `BERT_DEVICE=auto` выбирает CUDA, Apple MPS или CPU.

```sh
uv sync --locked
uv run bert/train.py
uv run bert/test.py validation
uv run bert/test.py test
uv run jev.py
```

Первый запуск обучения скачивает базовую модель. Каждый из трёх классификаторов
fine-tune обучает полностью, включая энкодер. После каждой эпохи считается
validation macro-F1; лучшая версия сохраняется в `bert/weights/{topic,urgent,sentiment}/`
вместе с токенизатором и конфигурацией. `training.json` содержит параметры,
пути к датасетам и историю эпох. В конце обучения рядом сохраняется
`training_curves.png`: средний train loss и validation macro-F1 по всем эпохам
для каждой задачи. Повторное обучение требует нового
`BERT_OUTPUT_DIR`, чтобы не затереть веса.

`test.py validation` использует `VALIDATION_FILE`, `test.py test` — `TEST_FILE`.
Без аргумента `test.py` оценивает тестовую выборку. Оба режима используют
библиотечные метрики scikit-learn через общую функцию `metrics()` из `train.py`.
Jev обрабатывает все записи из `INPUT_FILE` и сохраняет ответы в `OUTPUT_FILE`.
В скриптах для `INPUT_FILE` и `TEST_FILE` указан один и тот же тестовый файл. Для Jev нужен ключ; выполняются 48 платных запросов
на текущем синтетическом тесте. BERT сохраняет метрики accuracy/macro-F1 и
precision/recall/F1 по классам, а также ID, предсказания и вероятности в
`results/bert/`. Повторная оценка BERT заменяет предыдущие результаты этого
разбиения. Время inference включает токенизацию, без загрузки модели и без
прогрева; оно не является полноценным бенчмарком задержки.

В `data/authored-v2/` находятся 240 индивидуально написанных синтетических
обращений: train — 144, validation — 48, test — 48. Прежний шаблонный корпус
заменён. Тексты и метки назначены отдельно каждой записи, без комбинаций фраз
и без скрипта генерации. Во всех частях представлены 24 сочетания темы,
срочности и тона; классы сбалансированы.

Проверено отсутствие полных дубликатов после нормализации регистра и пробелов,
повторяющихся предложений между частями и пересечений ID/групп. `all.jsonl`
соответствует объединению частей. Правила разметки и результаты проверки
указаны в `manifest.json`. Это небольшой стартовый корпус для fine-tune:
он написан ассистентом, независимо человеком не размечен и не заменяет реальный
тест. Проверка буквальных совпадений не доказывает отсутствие близких по смыслу
примеров.
