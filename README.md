# Jev vs BERT

Репозиторий для сравнения Jev через API в режиме zero-shot и дообученного
`google-bert/bert-base-uncased` на обращениях в поддержку. Обе модели определяют
тему, срочность и тон одного и того же текста. Скрипты позволяют обучить три
классификатора BERT, оценить качество на общем тесте и измерить задержку,
пропускную способность и оценочную стоимость API-запросов.

Результаты проведённого эксперимента — в [REPORT.md](REPORT.md).

## Датасет

`authored-v2-en` — 240 синтетических англоязычных обращений,
написанных ассистентом. Корпус предназначен для пилотного
сравнения и не отражает качество на реальных обращениях.

| Выборка | Файл в `data/authored-v2-en/` | Обращений |
|---|---|---:|
| Обучение | `train.jsonl` | 144 (60%) |
| Валидация | `validation.jsonl` | 48 (20%) |
| Тест | `test.jsonl` | 48 (20%) |

Формат — JSONL: одна запись на строку, поля `id`, `group_id`, `text`, `labels`,
`source`, `language`. В каждой выборке классы сбалансированы и представлены
все 24 сочетания меток; ID и группы между выборками не пересекаются.

- `topic`: `billing` — платежи, `technical` — работа и настройка продукта,
  `sales` — покупка и коммерческие условия, `other` — остальные запросы.
- `urgent`: `1` — явная просьба о немедленной помощи или текущая остановка
  работы/продаж; `0` — остальные обращения.
- `sentiment`: `0` — недовольство, `1` — нейтральный тон, `2` — благодарность
  или удовлетворённость. Само описание сбоя не означает негативный тон.

## Quick start

Нужны **Python 3.14** и **uv**. Выполняйте команды из корня репозитория.

### 1. Установить зависимости

```sh
uv sync --locked
```

Зависимости из `uv.lock` устанавливаются в локальное окружение `.venv`.

### 2. Обучить и оценить BERT

```sh
uv run bert/train.py
uv run bert/test.py validation
uv run bert/test.py test --batch-size 1
```

Первое обучение скачивает базовую модель. Устройство выбирается автоматически:
CUDA, Apple MPS или CPU. Параметры обучения и пути заданы в начале
[bert/train.py](bert/train.py). Веса сохраняются в `bert/weights-en/`, метрики,
предсказания и матрицы ошибок — в `results/bert-en/`. Если веса уже существуют,
можно сразу перейти к оценке; для повторного обучения задайте новый
`BERT_OUTPUT_DIR`.

### 3. Запустить Jev и оценить ответы

Создайте `.env` по образцу [.env.example](.env.example) и заполните
`TYPESAFE_API_KEY`:

```dotenv
TYPESAFE_API_KEY=your_api_key
```

```sh
uv run jev.py run --output results/jev_quickstart.jsonl
uv run jev_evaluate.py results/jev_quickstart.jsonl
```

По умолчанию Jev обрабатывает 48 тестовых обращений: один платный API-запрос
с тремя вопросами на обращение. Ответы сохраняются в указанном JSONL,
метрики и матрицы ошибок — в `results/jev-en/`. Оценка сохранённых ответов
не обращается к API. Для повторного запуска укажите новое имя `--output`:
существующий файл не перезаписывается. Настройки модели и входного файла
находятся в начале [jev.py](jev.py); их также можно задать через `--model`
и `--input`.

Телеметрия обоих подходов сохраняется в подкаталогах `telemetry/` внутри
каталогов результатов. `--batch-size 1` у BERT позволяет сравнивать задержку
на одно обращение с Jev.
